## 当前推荐：独立后台服务

用户希望不依赖前台插件、自动同步并控制 ERP 负载。已增加独立 Node.js 进程：专用 Edge 无界面采集、进程计时、本机 SQLite、变化记录去重、持久队列、分批限速发送与本地状态页。使用方法、真实数据与性能验收、实时性边界见 [后台服务说明](docs/BACKGROUND-SERVICE.md)。

**只需双击“打开自动同步.vbs”（或“打开自动同步.cmd”）。** 自动安装运行依赖、启动后台并打开控制页面；首次在同一页面登录平台、连接 ERP，此后打开即恢复。默认每 10 分钟启动一轮，上一轮未结束时不重叠运行。关闭页面继续采集，页面有“停止服务”按钮；重复打开复用当前服务。

ERP 手机号和密码仅首次授权使用，采集服务不保存密码，专用令牌保存在本机。无需填写公会名称：自动按完整 UID 和抖音号匹配已有主播，根据 ERP 档案分组；公会未登记也可同步准确匹配的主播。平台昵称或游戏后缀变化不影响 ID 对应的主播记录。未匹配者留在本机待核对，不阻塞已匹配主播。0.5.0 优先每10分钟读取当天累计快照，历史日汇总每6小时复核；状态页可选择单日或最多31天的日期区间，选择后立即排队重采，数据中心页面的总音浪、开播总时长和独立 ACU 会逐日保存。ERP“我的主播”的签约/合作档案及个人详情显示主播 ID、抖音号、昵称、粉丝数、每日音浪、直播时长、ACU，支持日期选择。可见页面每30秒刷新落库数据，当天标记为暂估且不参与结算。真实数据与性能验证见 [接入验收记录](docs/ERP-SERVICE-ACCEPTANCE.md)。

2026-10-27已部署并核对真实生产回执：291位准确匹配主播的当天七项指标及580份历史日记录已入库。本机已经启动，原登录和专用授权保留；其他电脑首次使用仍需登录。未匹配和身份冲突保留待核对，详细计数、时间与稳定性边界见验收记录。

0.3.5历史改动：删除网页和兼容命令入口的公会手填步骤，支持空公会及多个公会自动分组，合计每30秒最多发送50条。昵称相同、UID冲突、重复档案不会模糊绑定，逐条记录待核对原因；任一新授权创建失败会撤销本次已创建令牌，保留原授权。日数据还会核对平台请求的日期、页码及完成状态，避免日期标签先变而旧表格尚未更新。该阶段79项回归、Edge离线操作和接收端临时数据库联调通过；当前0.4.0生产状态见上文。

以下保留旧扩展说明。独立服务是本轮推荐验收路径；不要把旧 0.1.4 安装包当作服务安装包。

Chrome / Edge Manifest V3 扩展。从你已登录的直播服务平台读取主播 ID、抖音号、昵称、粉丝数，以及所选日期范围内每位主播每天的总音浪、开播总时长和独立 ACU 指标。提供本地预览、搜索、CSV / JSON 导出、暂停与断点继续。

## 安装与使用

1. 在 Edge 打开 `edge://extensions`（Chrome 为 `chrome://extensions`），启用“开发者模式”。
2. 点击“加载解压缩的扩展程序”，选择本项目的 `extension` 文件夹。也可以先解压 `artifacts/tiktok-auto-catch-v0.1.4.zip`，再选择含 `manifest.json` 的解压目录。ZIP 不能直接当作已签名扩展安装。
3. 在安装扩展的同一浏览器登录直播服务平台。Codex 内置浏览器的登录不等于 Edge / Chrome 已登录。
4. 点击扩展图标打开“主播数据桥”，选开始和结束日期，点击“开始采集”。日期范围包含首尾，单次最多 31 天，只支持昨天或更早的完整日期。采集期间保持浏览器开启、平台登录有效；后台标签页自动翻页，不要手动调整其筛选条件。
5. 任务完成后，搜索和检查数据，然后导出 CSV / JSON。搜索后的导出仅包含筛选结果；清空搜索可导出全部记录。

安装后如平台标签页已开着，请刷新一次。更新已有安装时，先将新包内容覆盖到**原来加载的扩展目录**，再在扩展管理页点击该插件的“重新加载”，关闭旧仪表盘并重新打开；仅解压到其他目录再点重新加载，不会让原插件使用新文件。不要卸载插件，以免丢失本地记录。选择“继续采集”，切勿用“开始采集”替代。新版会校验仪表盘、后台和采集页面的版本是否一致。

异常状态会显示“导出采集诊断”，报告将已保存的错误现场与导出时的只读表格现场分开，包含阶段、页码、实际保存数量、加载状态和实际运行版本，不含 Cookie、令牌或整页 HTML。原采集标签页关闭时，“继续采集”会重建标签页。新任务会替换当前批次，本地仅保存一批数据。

如果此前错误显示隐藏页面检查次数过少，或本次检测到明显计时延迟，插件会把采集标签页切到前台恢复采集。请保持采集页可见，完成后再打开仪表盘查看结果；浏览器最小化、休眠和后台节能可能延迟页面任务。插件只自动重试一次，失败仍保留断点与本地记录。

## 字段口径与质量

| 字段 | 来源与单位 |
| --- | --- |
| 主播 ID | 平台 UID；字符串保存，避免长整数精度损失 |
| 抖音号 / 昵称 | 主播身份信息；不按昵称匹配档案 |
| 粉丝数 | 当前主播列表“粉丝指数”的采集时快照，非历史每日粉丝数；优先读取悬浮精确提示 |
| 每日音浪 | 主播数据报表该日“总音浪”，不是礼物音浪或近30日音浪 |
| 直播时长 | 该日“开播总时长”，规范为秒，页面显示小时/分钟/秒 |
| ACU | 指标配置里的独立 `acu`，不能用 `feed_acu` 或人气峰值代替 |

插件在报表缺少 ACU 时自动勾选所需指标，这会保存平台显示列配置；不改变主播信息。仅在平台提供可读的精确提示时采用精确值，否则保留近似标记 `≈`，不伪造精度。缺失值留空，不当成 0；历史日期出现已离会主播时保留每日数据，并标注缺少当前粉丝档案。JSON 保留原始显示值、精确提示和采集时间，便于复核。

CSV 已转义公式前缀。Excel 打开 CSV 时仍可能自动转换长 ID，建议使用“数据 → 从文本/CSV”，把主播 ID、抖音号两列指定为文本；需无损保存可用 JSON。

## ERP 接入

ERP 使用独立的每日汇总和当天快照表、明确身份绑定、专用令牌、幂等与有界查询；不修改原有工资、结算或月度团队业绩。后台服务只有配置成功后才发送，未配置时保持零 ERP 请求。主播档案内的“抖音平台数据”读取自动采集结果，显示数据日期、采集和接收时间；与手工档案、周ACU等不同口径分别呈现。实际验证结果见 `docs/ERP-SERVICE-ACCEPTANCE.md`。

## 0.1.4 隐藏页面计时延迟修复

新收到的 0.1.3 报告确认后台与采集器版本一致。采集页已显示第 111–120 条，无加载动画、无解析错误，但处于隐藏状态，22 秒内仅检查了 5 次；最后已检测到一次有效的新页内容。旧等待循环在每次检查前判断超时，计时器迟到时会直接退出，漏掉确认新页稳定的最后一次检查。本地已按延迟计时的条件复现此缺陷。

新版通过 DOM 变化唤醒等待，并在计时器唤醒后先检查页面，再决定是否超时。仍未更新的页面不会当作成功；若检测到明显计时延迟，将采集标签页切到前台刷新，按同一断点仅重试一次。点击“继续采集”时也会识别旧报告中的隐藏页稀疏检查，优先在前台恢复。诊断新增实际等待时长、页面变化唤醒次数及最长唤醒间隔。

报告中的 110 条是本轮已核对数量，191 条是保留的本地档案总数；重验期间二者可以不同。升级保留这些档案与已验证断点，不需要重新开始任务。自动验证不等于真实平台全量验收，仍需在已登录的 Edge / Chrome 中验证后续分页与每日数据。

## 0.1.3 分页完整性与现场诊断

收到的 0.1.2 报告显示已推进到第 220 条，但实际保存 180 位主播；报告仅有仪表盘基础信息，无法据此确认真实超时的根因。此版在翻页后等待新页主播行稳定，写入前校验本阶段已见过的主播 ID，阻止重复页推进断点。加载检测会排除隐藏的动画；表格等待超时或发现重复页时，仅自动刷新重试一次，仍失败则保留断点。

旧任务缺少逐页身份校验记录时，“继续采集”会保留已保存的数据，从当前阶段的第一页重新核对。因此升级后进度回到第一页属于预期行为，不表示删除了已有的 180 条记录。诊断会区分旧任务错误与当前现场，并记录等待次数、表格内容变化次数、加载标记和实际适配器版本。此版已做本地自动验证，真实浏览器的全量采集仍待验收。

## 0.1.2 采集超时诊断

普通表格加载超时也会生成可导出的诊断；等待状态只检查主播表格区域，避免其他页面组件的加载动画挡住采集。错误任务提供断点、分页、表头、行数和加载标记等信息，旧版本已保存但没有诊断对象的错误任务也可导出基础诊断。真实平台上的最终效果仍需在已登录的浏览器内验证。
