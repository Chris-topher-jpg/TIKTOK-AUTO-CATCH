# 独立采集服务接入 ERP：待批准范围

日期：2026-10-27。根据用户“可不采用插件、能接入 ERP 并实时同步且不卡顿”的新需求提出。此前“修改 ERP 前先告知并申请同意”仍有效。ERP 当前仅只读检查，未改文件、未调用写接口、未部署。

## 已完成的独立部分

采集项目 service/ 下有独立浏览器、进程计时、本机数据库、版本记录、持久队列、只读状态页、导出与默认关闭的发送端。真实 Edge 无界面离线测试通过，且页面定时器彻底禁用时仍能翻页。不是已登录生产全量验收，也未证实该机构具备官方实时数据接口权限。

本地 ERP 的主播 CSV 导入支持档案 UID、抖音号、昵称和粉丝；逐主播逐日数据没有现成入口。旧月度团队业绩接口不能复用为逐日写入接口。生产版本是否具有同样导入入口需上线前复核。

## 推荐方案

独立主机/实例采集 → 本机数据库与持久队列 → 每批最多 50 条、并发 1、每次发送至少间隔 30 秒 → ERP 专用接收器 → 索引化快照/日汇总查询。

值未变不发送；UID 与日期做唯一业务键、覆盖更新不累加；近似和缺失值留待核对，不填 0。当前已实现的发送端只发送通过校验的历史日汇总；当日值暂存本地、明确标记暂估。要展示当日实时快照，必须先核实来源提供对应字段，再实现独立快照协议并明确观察时间、平台业务时间及暂估标志。

1. server/app.js：注册专用集成模块；接收端机器鉴权与现有用户登录路径隔离，不扩大其他 API 的机器访问范围。
2. 新增 server/douyin-anchor-ingest.js：专用接收接口、令牌哈希校验、请求体与批次上限、角色/机构范围、幂等、限流、审计和异常回执。对 UID/抖音号冲突或未绑定拒绝写入，不按昵称自动合并。
3. 新增 server/douyin-anchor-store.js：数据读取与写入、小事务、独立集成数据模型、UID+日期与机构索引；不在接收请求内执行全表扫描、工资结算或全量汇总。
4. server/db.js：仅按既有迁移方式增加集成表及必要索引，不重建/初始化现有表。初步拟定三个独立表：主播绑定、逐日日汇总、批次幂等/审计；是否需要实时快照独立表在真实来源验证后确认。
5. 新增 shared/douyin-anchor-daily.js：字段/日期/数值/暂估定义、单位和幂等协议。专用集成令牌最小权限，可撤销，不记录明文，不使用用户密码或复用 Cookie。
6. 新增 tests/douyin-anchor-ingest.test.js 与 tests/douyin-anchor-load.test.js：权限/范围、重复批次、并发重试、乱序更新、数据精度和锁等待验证，只用测试数据库。

上述范围为先落库、可查询和状态监控；ERP 页面新增实时看板、菜单与角色可见范围需列出实际前端路径后再申请，不隐含在本次接收端批准中。会先在干净工作区实现，保留当前 ERP 的其他未提交变更。

## 性能验收和发布

不承诺绝对零卡顿。采集从 ERP 进程与机器资源隔离；ERP 仅承担受限的小批写入与分页读。先对当前核心 API 与数据库做基线，至少覆盖实测主播总数、近 31 天历史与持续重复刷新；再比较启用同步后的 P95、错误率、Node 事件循环延迟、锁等待、CPU/内存与队列积压。

建议门槛：核心 API P95 劣化 ≤10% 或 ≤50ms 中较宽的一项；无新增 5xx、无锁超时；停接收端后不丢队列、恢复后不重复累计。超过阈值减批、延长间隔或熔断同步，ERP 业务优先。门槛还需用户确认，不是当前测得结果。

本地 450 条采集库写入测试只是独立进程参考，不能作为线上 ERP 性能保证。ERP 完成后按本项目 AGENTS.md 执行验证、开发分支与 main 集成、备份、迁移演练和正式部署，最后核对线上 revision；用户同意前不执行这些 ERP 改动。
